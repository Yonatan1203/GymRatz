Design Section 3 — Animation System

Subtle, swift animations (150-250ms) that make the app feel alive

Animation Primitives — Shared Widgets

These reusable animation widgets get built once and used everywhere. All use Curves.easeOut.

FadeIn 200ms

Opacity 0→1. Used for: screen content appearing, cards loading in, empty states.

SlideUp 200ms

Translate Y 16px→0 + fade. Used for: content sections appearing on screen load.

StaggeredList 50ms delay between items

Each child slides up with a cascading delay. Used for: workout lists, program cards, menu items, stats grids.

ScaleTap 150ms

Scale 1.0→0.97 on press, back to 1.0 on release. Used for: all tappable cards and buttons. Subtle press feedback.

AnimatedProgress 250ms

Progress bar fills from 0→value with easing. Used for: program progress, onboarding progress bar, completion rings.

Page Transitions

Tab switching

Cross-fade between tabs (200ms). No slide — tabs are siblings, not a stack.

Push navigation

Shared axis slide-right (250ms). Standard iOS/Material feel. Back = reverse.

Modals & bottom sheets

Slide up from bottom + backdrop fade (200ms). Standard pattern.

Onboarding steps

Horizontal slide (next = left, back = right) with content fade. Progress bar animates between steps.

Micro-Interactions

Set completion

Checkmark animates in + row briefly highlights with coral tint. Haptic already exists.

Workout complete

Stats count up from 0 (duration, volume, sets). Brief celebratory moment.

Bottom nav tap

Icon scales 1.0→1.15→1.0 (150ms) on active. Subtle but noticeable.

Pull to refresh

Custom refresh indicator with rotation animation instead of default spinner.

What We're NOT Doing

  • No spring physics or bouncy overshoot — this isn't Duolingo
  • No parallax scrolling — adds complexity without value
  • No hero animations between screens — overkill for a fitness tracker
  • No animated backgrounds or particle effects
  • No animation on every single element — only where it serves UX
